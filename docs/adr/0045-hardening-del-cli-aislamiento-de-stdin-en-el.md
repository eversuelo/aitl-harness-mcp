# ADR-0045 — Hardening del CLI: aislamiento de stdin en el TUI, deadline de streaming, registry por sub-agente y fail-fast de DB

- **Status:** accepted
- **Date:** 2026-07-06

## Context

Reporte de usuario (2026-07-05): `aitl chat` "se traba" y cada tecla hay que pulsarla dos veces. Reproducido determinísticamente en pty (script -qec + stub OpenAI-compat en :1234): el menú interactivo deja stdin en flowing mode (stdin.resume() al arrancar) y suspend() no lo pausaba; el chat hijo corre con stdio:"inherit" sobre el MISMO fd de TTY, así que padre e hijo se reparten los bytes del teclado ~50/50 (se tecleó "hola como estas", el REPL recibió "hocai"). La auditoría disparada por este bug encontró además: spinner no idempotente que borraba los primeros ~15 chars de la respuesta streameada; SIGINT del chat con process.exit(130) a pelo (huérfanos los hijos de servidores MCP y conexiones DB abiertas); consumeStream sin deadline (un backend local que acepta y se cuelga sin cerrar el SSE = spinner infinito, withRetry nunca dispara); sub-agentes del orchestrator compartiendo el defaultRegistry global y sus gates mutables; preAction que tragaba el fallo de conexión Mongo y dejaba seguir el comando; spawns del TUI sin handler de error (ENOENT tumbaba el panel) y kill no-árbol en POSIX (Vite huérfano reteniendo el puerto); ShellTool con maxBuffer 1MB que lanzaba perdiendo el output; y `limit` sin validar en la API (NaN → sin tope en rutas de lectura sin auth).

## Decision

Commit 48d7fda (rama fix/cli-chat-stdin-hardening): (1) src/interactive/menu.ts: suspend() hace stdin.pause() mientras corre la acción adjunta y resume() al restaurar; los "Press Enter to return" reanudan explícito; commandMode re-pausa tras cerrar su readline; handlers de spawn error en los 3 puntos; tree-kill POSIX con process group (spawn detached + kill(-pid)). (2) src/repl/chat.ts: clear del spinner idempotente; SIGINT cierra mcpMount + closeClient con backstop de 2s. (3) src/orchestration/stream.ts: deadline de inactividad entre deltas, default 180s, configurable AITL_STREAM_IDLE_MS (≤0 desactiva); el error contiene "timeout" → transitorio → withRetry replantea el turno; gen.return() cierra el HTTP stream. (4) src/orchestration/orchestrator.ts: ToolRegistry fresco por sub-agente (overridable vía subAgentOpts.registry); el CLI ya pasa installDefaultTools:true así que cada registry recibe sus tools. (5) src/cli.ts: preAction hace process.exit(1) con mensaje claro si ningún Mongo conecta; "models" añadido a NO_DB_COMMANDS. (6) src/providers/base.ts: await explícito dentro del wrapper no-streaming de FallbackProvider.chatStream. (7) src/tools/shell.ts: maxBuffer 16MB + clip head/tail a 30k chars. (8) src/server/api.ts: parseLimit (clamp def/max 500) en las 5 rutas de lectura.

## Consequences

- El chat desde el TUI recibe todas las teclas (verificado E2E en pty: input íntegro, texto streameado íntegro, ciclo chat→/exit→menú→q limpio; typecheck, 104/104 tests, build). - Ningún run puede colgarse indefinidamente en streaming; el costo es que un turno legítimamente silencioso >180s se replantea (ajustable por env). - Ctrl+C ya no acumula procesos MCP huérfanos entre sesiones. - Los gates de un sub-agente ya no contaminan a sus hermanos; quien quiera compartir registry lo pasa explícito. - Un Mongo caído corta el comando al inicio con hint (`aitl check-db`) en vez de un stall confuso. - Pendientes documentados en la auditoría: auth de la UI web (RBAC deja las escrituras muertas), unificación de las 3 conexiones Mongo, destino de buildGraph, migración validateSync, tests de integración de API/MCP.
