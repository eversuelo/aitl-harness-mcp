# ADR-0069 — Siembra operativa del registro (skill-router, memoria-sesion, agents, conventions) + RBAC de definition-tools

- **Status:** accepted
- **Date:** 2026-07-11
- **Components:** src/mcpserver, src/projectctx, skills, docs, AGENTS.md, Functions.md

## Context

La verificación 2026-07-11 de la inyección de contexto (agents/skills/roles/pair_programming) y quality gates destapó que el mecanismo estaba sano pero el registro casi vacío y con huecos de confiabilidad: (1) BD con solo 2 skills y 0 agents reales (list_agents devolvía únicamente los 5 roles kind:role); (2) colección conventions VACÍA y sin superficie CLI/MCP que la llenara (loadConventions existía solo como API de librería) — hydrate inyectaba 3 de sus 4 secciones; (3) software/repo del propio harness ausentes del catálogo (get_software("aitl-js") = null); (4) TOOL_RBAC contradecía su propio contrato: write_agent/write_skill/delete_agent/delete_skill/save_mcp_context/record_human_intervention mutan estado sin gate RBAC (un token auditor read-only podía escribir/borrar definiciones), mientras build_definition sí estaba gateada; (5) routeSkills (Pilar 3) tenía CERO tests y un micro-bug: con presupuesto agotado, content.slice(0, negativo) inyectaba un fragmento basura en vez de descartar la skill; (6) Functions.md no documentaba ninguna de las 52 tools MCP; (7) espejo docs/adr/ en 0061 vs ledger real 0068, con tres afirmaciones de contigüidad distintas en docs; (8) tres superficies de inyección con capacidades distintas sin documentar (run-host y el hook hydrate NO llevan skills/agents/roles); (9) pair_programming a medio implementar: mode "pair" se ejecuta idéntico a review (una crítica al cierre) y role.triggers es un campo persistido que nada lee; (10) las skills __global__ (adr-ledger-reconcile) no se auto-enrutan (el router solo consulta el project del run); (11) PhaseGate sin consumidores; (12) el hook generado por aitl init sigue en UserPromptSubmit contradiciendo ADR-0023 (SessionStart); (13) las 4 tools de historial de versiones no pasan por runLogged (sin telemetría mcp_tool_calls).

## Decision

Sembrar el registro completo usando las propias tools del harness y cerrar los huecos de código de bajo riesgo: (a) software aitl-js → project aitl-js → repo AITL-Harness-JS (write_software/write_repo, nombres idempotentes con aitl init); (b) skills nuevas skill-router (meta: tabla de enrutamiento tarea→skill/rol/agente con límites del router explícitos) y memoria-sesion (checklist de cierre: una memoria por hallazgo + ADR con next-free verificado + record_prompt + sync --pull + verificación de recall), registradas en Mongo y espejadas como skills/{skill-router,memoria-sesion}/SKILL.md; (c) agent harness-engineer (brief operativo con verify obligatorio); (d) conventions sembradas desde la sección ## Conventions del AGENTS.md regenerado (8 reglas: 6 error, 2 warn) vía loadConventions; (e) AGENTS.md regenerado como contrato operativo + registro + mapa de inyección (3 superficies) + tabla de gates; (f) docs/MAPA-SKILLS.md con el mapa completo (diagrama, triggers, límites, mantenimiento); (g) Functions.md §14 documenta las 52 tools MCP (parámetros de los schemas reales, RBAC por tool, notas de telemetría); (h) fix TOOL_RBAC: +6 entradas (write/delete de agent y skill → agents_skills; save_mcp_context y record_human_intervention → memory:create, mismo catch-all que run_agent), tabla exportada y con canario en src/mcpserver/rbac.test.ts (biyección con el set mutante de 25); (i) fix router: Math.max(0, presupuesto) evita el slice negativo, y primera suite src/projectctx/router.test.ts (selección, fallback a recencia, filtro de roles ADR-0063, presupuesto). Verificación E2E viva contra Mongo: router skills → [memoria-sesion, repo-indexer, skill-router]; router agents → [harness-engineer] con los 5 roles excluidos; hydrate sections {memory:6, decisions:5, conventions:8, repomap:1} (primera vez con las 4 secciones); gate determinista VETO .env / ALLOW src/cli.ts; suite 438/438 (antes 401).

## Consequences

El router deja de ser un mecanismo sin contenido: hay skills/agents reales que enrutar, con contrato probado por tests, y hydrate inyecta por primera vez sus cuatro secciones. Los escritores/borradores de definiciones quedan bajo RBAC auditado como su contrato prometía. Quedan DOCUMENTADOS y pendientes (no resueltos aquí, cada uno pedirá su ADR): pair continuo + role.triggers muertos; inclusión de __global__ en el router (E6/ADR-0038); exponer roles en run_agent MCP; PhaseGate sin cablear; reconciliar ADR-0023 vs hook UserPromptSubmit; runLogged para las 4 tools de versiones; y el plan de repo map v2 (ADR-0070, proposed). El espejo docs/adr y los punteros de contigüidad se re-sincronizan con aitl sync --pull en esta misma sesión.
