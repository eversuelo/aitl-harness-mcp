# ADR-0071 — Interop multi-harness v1: tools MCP synthesize + coord_status + publish_event y slot de providers agnóstico (Chutes)

- **Status:** accepted
- **Date:** 2026-07-12
- **Components:** src/mcpserver, src/memory, src/coord, docs, .env.example

## Context

El usuario quiere que el harness funcione CON otros harneses (Claude Code, Codex, Antigravity/agy, OpenCode): (a) que la síntesis del conocimiento sea invocable vía MCP y la ejecute un agente sintetizador propio del server (sonnet/haiku/local) cuya respuesta se re-ingrese al flujo del llamador; (b) un status de coordinación para agentes concurrentes — la necesidad quedó demostrada en vivo el 2026-07-11: una sesión paralela ajena apareció editando graph.ts/adrGuard mientras esta sesión trabajaba, sin forma de verla desde el MCP. Además: la key de Chutes.ai estaba INERTE en una variable API_KEY que el harness no lee (la clasificación por prefijo solo conoce sk-ant-*/sk-or-*; cpk_* no casa), y no existía guía de agnosticismo de providers. Piezas preexistentes verificadas: Synthesizer ya acepta Provider inyectable (synthesizer.ts:96-101) con fallback extractivo anti-blanco (ADR-0059); coordinación v1 con task_claims/coord_events/poll (ADR-0054) tenía el lado pub sin exponer (recordCoordNote solo interno); run_agent es el precedente de tool MCP que conduce un modelo con RBAC; el server corre stdio+HTTP+socket.

## Decision

Tres tools nuevas en buildServer (52→55), todas por runLogged (telemetría mcp_tool_calls + RBAC): (1) `synthesize` {project, provider: auto|anthropic|openrouter|lmstudio|openai-compat|extractive, force=true, compact=false, return_text=true} — compresión rodante ejecutada por el provider del SERVER elegido POR INVOCACIÓN (getProvider/getProviderWithFallback; auto degrada a extractivo si no hay backend; un provider explícito que no resuelve lanza error accionable); devuelve slugs + stats + cuerpos de síntesis (cap 8k chars c/u) para re-inyección inmediata por el agente llamador — re-ingreso durable (Mongo→hydrate) + inmediato (tool result). RBAC memory:update. Las credenciales del modelo viven en el server: cualquier host MCP dispara síntesis sin poseer keys. (2) `coord_status` {project, events_limit=20, include_history} — read-only: claims ACTIVOS (listClaims: released:false y no expirados) con expires_in_ms, eventos recientes desc y actores (dueños∪actores de eventos, last_seen + open_claims). (3) `publish_event` {project, type: note|task_done|decision, task_key?, payload} — expone recordCoordNote (best-effort {ok:false}, nunca lanza) como el lado pub del bus; RBAC coordination:create. Providers: .env real recableado (API_KEY→OPENAI_COMPAT_API_KEY; OPENAI_COMPAT_BASE_URL=https://llm.chutes.ai/v1, MODEL=default, MODEL_PRIMARY=openai-compat determinista por decisión del usuario — solo Chutes activo + slot Anthropic listo), claves LM Studio retiradas del .env del repo Y de ~/.aitl/config.json global (sin riesgo: ADR-0067 re-autodetecta el modelo cargado vía la URL default cuando el server local corre); .env.example documenta el slot openai-compat con ejemplos Chutes/OpenAI y el límite del prefijo cpk_*; guía nueva docs/PROVIDERS.md (4 slots, cadena auto anthropic→openrouter→lmstudio→openai-compat, recetas mínimas, keys sin multiplicar .env vía ~/.aitl/config.json y perfiles ADR-0061). Verificación: cliente MCP en memoria (InMemoryTransport) → 55 tools; publish_event ok:true con telemetría; coord_status proyecta eventos reales (los decision de ADR-0069/0070); synthesize extractivo limpio en proyecto vacío; aitl models → openai-compat activo; auth Chutes HTTP 200; suite 439/439; canario RBAC ampliado (biyección 27 mutantes).

## Consequences

Cualquier host MCP (Claude Code, Codex, Antigravity, OpenCode — todos montan el server por .mcp.json/config.toml/opencode.json; stdio o HTTP) puede: disparar síntesis del conocimiento ejecutada por el modelo del harness y re-inyectarla a su flujo; ver quién trabaja en el codebase y en qué; y publicar hitos para sus pares. El bus de coordinación queda completo en su v1 pull (claim/release/publish/poll/status) — el modelo consume en fronteras de turno (el hook Stop ya corre coord poll). Deuda aceptada: sin canal push (MCP es request-response; ver ADR-0072 proposed), synthesize sin scope por categoría ni budget_ms propio (una síntesis de banco enorme puede rozar el timeout del cliente MCP), y el modo pair/roles sigue como en ADR-0069. Riesgo del cambio de providers: los runs del repo ahora consumen Chutes (de pago) al no haber backend local activo; el laboratorio raytracer conserva LM Studio por autodetección.
