# ADR-0044 — Provider Anthropic directo + AITL_API_KEY único + fallback entre backends + chat estilo Claude Code (enmienda ADR-0020)

- **Status:** accepted
- **Date:** 2026-07-02

## Context

ADR-0020 consolidó OpenRouter como único provider de modelo crudo; ADR-0038 añadió lmstudio/openai-compat para el piloto local. Quedaban tres brechas: (1) features de la API first-party de Anthropic que no sobreviven un gateway OpenAI-compatible — prompt caching (cache_control, ~0.1x en lecturas, métrica #7 de tokens), structured outputs (output_config.format) y bloques tool_use/tool_result nativos; (2) la salida JSON de modelos locales pequeños (gemma-4 vía LM Studio) era frágil — el walker de brackets + repair-retry de ADR-0043 parchaba el síntoma, no la causa; (3) la configuración multi-provider exigía conocer 4+ variables y el chat (ADR-0003) era un REPL mínimo sin visibilidad de tools/tokens ni selección de backend.

## Decision

1) AnthropicProvider (src/providers/anthropic.ts) con @anthropic-ai/sdk 0.109 (NO el shim OpenAI-compat): system como bloque cacheable (cache_control ephemeral), tools nativas, adaptador toAnthropicMessages (tool→tool_result mergeando resultados consecutivos en un solo turno user; tool_use sin id sintetiza uno; assistant vacío se salta) + tests. Modelo default claude-opus-4-8. 2) Constrained decoding opt-in: CompleteOpts.jsonSchema → response_format json_schema en OpenAIProvider (grammar en LM Studio/llama.cpp) y output_config.format en Anthropic; decomposeTasks lo usa con fallback al prompt plano — el backend garantiza JSON parseable en vez de confiar en el modelo. 3) Config simplificada: AITL_API_KEY único clasificado por prefijo (sk-ant-*→anthropic, sk-or-*→openrouter; la key explícita del provider gana). 4) providerStatus() + comando `aitl models [--json]`: objeto de backends configurados, activo y cadena de fallback. 5) FallbackProvider: --model auto detecta el primer backend configurado (MODEL_PRIMARY gana si está configurado) y encadena el resto; en fallo duro replay en el siguiente backend; un stream a medias NO se replaya silenciosamente. 6) Chat estilo Claude Code (src/repl/chat.ts, evoluciona ADR-0003): colores/spinner/historial sin deps nuevas, slash commands (/help /models /model /tools /tokens /new /id /ask /exit), trazado de tool calls en vivo vía nuevo hook RunAgentOpts.onTool (observacional; la auditoría no cambia), status line por turno (provider, s, tokens ↑↓, iters, tools, vetos, runId corto); RunAgentResult ahora expone token_usage y tool_calls; --project opcional ($AITL_PROJECT o basename del cwd). 7) TUI: submenu Chat (auto/--ask/--mcp/por provider) + atajo "c" + entrada Modelos.

## Consequences

Positivas: el piloto puede medir caching real de Anthropic (métrica #7); el JSON de modelos 4B locales pasa de frágil a garantizado por gramática (la clase de bugs de ADR-0043 desaparece donde el server soporta response_format); onboarding con UNA variable (AITL_API_KEY); resiliencia ante caída de un backend sin intervención; el chat sirve como superficie de observación del loop (tools/gates/tokens visibles). Negativas/deuda: ADR-0020 queda enmendada (ya no hay "único gateway"); el FallbackProvider reporta capabilities() del primario (un fallback a un backend menos capaz puede degradar tool-use silenciosamente); thinking de Anthropic queda deshabilitado a propósito (el ChatTurn normalizado no transporta thinking blocks — habilitarlo requiere extender la persistencia del transcript); countTokens sigue siendo estimación ~4 chars/token. Verificado: typecheck limpio, 104/104 tests, build ok, `aitl models`/`chat --help`/REPL smoke-tested; falta corrida viva contra API real de Anthropic (sin key en este entorno).
