# ADR-0033 — Roles de ingenieria componibles (H11) que asisten la decision del ingeniero + metrica de supervision humana

- **Status:** accepted
- **Date:** 2026-06-28

## Context

H11/objetivo-6/pregunta-11 prometian EVALUAR roles de ingenieria (DevOps/Security/QA/Arquitectura, pair-programming) pero no existian — la mayor brecha de tesis (auditoria: core ausente). El usuario pidio construir el MVP y cerrar la brecha, recalcando que los roles deben ASISTIR al Software Engineer a decidir con mejor criterio (no decidir por el). Ademas faltaba la metrica Tabla 4.3 #6 (supervision humana / record_human_intervention).

## Decision

Roles como overlay componible sobre primitivas existentes (sin runtime paralelo, sin nueva coleccion). src/roles/: schema.ts (Role = name+lens(persona)+mode+severity+triggers+denyGlobs+skills+binding; tipos RoleVerdict y DecisionBrief), store.ts (RoleStore sobre la coleccion agents discriminada por metadata.kind=role, reusa DefinitionStore), engine.ts (roleGate determinista=PermissionGate via denyPathsGate, sin modelo; reviewWithRole=critica por modelo; deliberate=corre todos, atribuye objeciones por rol, emite eventos y arma DecisionBrief), seed.ts (catalogo: security[gate/blocking], devops[review], qa[pair], architect[gate/blocking], devsecops[review]). Tres modos de acoplamiento (E2): gate=veto bloqueante en el loop (determinista), review=critica en checkpoint fin-de-run, pair=acompanamiento (advisory). Eventos nuevos review/role_veto/deliberation (+ human_intervention) para trazabilidad de objeciones. Integracion en runAgent: opts.roles carga roles; gate-mode se instalan como PermissionGate (veto con razon atribuida [role:x]); review/pair deliberan sobre finalText al cierre y devuelven decision_brief (+ run.roles/decision_blocked persistidos). El brief ASISTE: stance approve|concerns|block + findings + recommendation por rol; blocked solo si un rol blocking objeta, pero el humano decide. Superficie: CLI aitl role {seed,list,rm,gate-check}, aitl review <target|@file> --roles, aitl run --roles; MCP list_roles/write_role/seed_roles (gated agents_skills). Metrica #6: evento human_intervention + CLI aitl intervene <runId> --reason --minutes + MCP record_human_intervention; aitl run-show ahora reporta human_interventions{count,minutes}, roles, decision_blocked y review_events.

## Consequences

H11 deja de ser una hipotesis sin artefacto: ahora es evaluable (worker-solo vs worker+roles; objeciones atribuidas y trazables en events). El gate determinista corre SIN OPENROUTER_API_KEY (demostrable ya); review/pair (por modelo) requieren key como el resto del loop. Roles reusan agents+gates+events: cero runtime paralelo, desmontables. run-show cubre mas de la Tabla 4.3: #1 velocidad (duration), #6 supervision humana (count+minutes), #7 eficiencia (tokens/iters/tool_calls), #8 memoria (hydrate), #9 trazabilidad (events incl. objeciones de rol). Siguen externos/parciales: #2 % pruebas (gate pass/fail via --verify-cmd), #3 regresiones, #4 mantenibilidad, #5 seguridad (parcial: gate/role_veto + slice validateTenantIsolation). Verificado: 40 tests; seed 5 roles, gate-check VETO .env (atribuido a security) / ALLOW src/app.ts; run --roles operativo. Diseno DSR: un rol de ingenieria = composicion declarativa de primitivas (persona+skills+gate+binding+modo) con un brief que asiste (no sustituye) el criterio humano; nombrar los tres acoplamientos (checkpoint/continuo/bloqueante) y atribuir cada objecion es el conocimiento reutilizable de H11.
